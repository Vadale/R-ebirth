# I1 native-client workflow acceptance

The [I1 plan](../../docs/i1-assistant-plan.md) fixes the scope and acceptance.
This directory separates deterministic packaging checks from live assistant
runs. Nothing here requires relm, a GGUF model or a native build.

## Model-free checks

```sh
python3 tests/assistant-integration/test-tools.py
Rscript --vanilla tests/skills/r-statistical-analysis/test-runner.R .
```

The Python tests exercise explicit installation destinations, content integrity,
reproducible archive contents and missing-R recovery. The existing R tests cover
artifact validation and retained failures/warnings. They run in the ordinary R
CI matrix; live authenticated assistant runs do not.

## Explicit native-client evaluation

`cases.json` contains the fixed prompts, modes and separate reviewer
expectations. Expectations are never sent to the evaluated client. Only the
simple and longitudinal cases test language-unspecified statistical discovery;
the guided case explicitly invokes the skill. Other cases test inadequate data,
missing packages, fit warnings and an explicit Python preference.

Run the installed Codex CLI with its ordinary authentication and sandbox. The
evaluation harness does not install or modify personal skills/configuration.
Inspect the actual initial skill inventory once before the sample and record
its source hash. If a selected model is unavailable, preserve the failed attempt
and choose only a model available to that client/account; do not silently alter
global settings or claim the failed model was tested successfully.

```sh
python3 tests/assistant-integration/run-client.py /absolute/new-evidence-dir \
  --model <available-model> --reasoning medium
```

Use the host's detached execution/completion mechanism for this command. The
harness executes cases sequentially, with a 600-second per-case watchdog, no
automatic retry and immediate stop on client infrastructure failure. Each case
has a fresh workspace, exact prompt, client events, final response and receipt;
`status.json` is written atomically. An interrupted harness may leave `running`;
verify the process before diagnosing, and never interpret it as completion.
Keep failed directories instead of overwriting them. `--case ID` permits a
justified affected-case continuation in a new directory.

The live client may consume subscription allowance. Do not run this suite in
ordinary CI, repeatedly optimize against these prompts or count a successful
process exit as statistical acceptance. A small fixed sample cannot estimate a
general selection rate. Ambient skills and client instructions are confounders;
record them and distinguish selection from quality of the subsequent analysis.

## Data and review

All inputs are synthetic. The simple fixture is generated by the harness from
two fixed vectors. The repeated-measures input reuses the earlier
`tests/skills/r-statistical-analysis/evidence/observations.csv` fixture: 60 people,
five visits each, two observational groups. Its provenance and earlier guided
analysis are separate from I1's native-client observations. The warning fixture
deliberately creates separation and uses one GLM iteration; inference should be
withheld. Insufficient data has one person per group, not independent replication.

`reference.R` calculates the simple Welch difference/interval and the complex
person-level change or OLS-slope sensitivity by arithmetic. It uses R's Student quantile,
not `t.test()` or the assistant's analysis script; this verifies calculations,
not an independent implementation of the distribution or of nlme. Check the
complex model's dependence, coding, units, counts and interpretation separately.

Inspect actual command events for skill loading and executed language, then
review code and artifacts. Replay only trusted, inspected analysis scripts in
fresh R processes and new directories; compare result tables numerically and
check warnings. Inspect the plots visually. Retain code/input/artifact SHA256,
client/model/version, actual timings and observed failures. Commit only relevant
synthetic artifacts and compact client receipts; do not publish unrelated user
configuration, authentication data or entire initial client prompts.

Observed results, fresh-process replay and retained limitations are recorded in
[`docs/i1-implementation.md`](../../docs/i1-implementation.md). Seven completed
client processes are not seven flawless analyses or an access-confinement claim.
