## Findings

1. **P2 — Zero-coefficient projection still copies rows during live capture.** `rebirth/src/rust/rebirth-llm/src/projection.rs:347` (row access), with the coefficient checked only at lines369–377. For a projected handle with `coef = 0`, `on_state` capture of that same component requests the ready callback through `live_trampoline`. Although projection's ask response is false, its ready handler still loops over every executed row, calls `relm_projection_row(..., false)`, checks finiteness and computes the norm before `project()` returns its zero no-op. This violates the explicit D046 zero-coefficient bypass of projection tensor copying/writing and adds all-row work and projection-specific failure/cancellation points to a supported zero-plus-live call. The capture's own read is separate and remains necessary. Preserve producer classification, occurrence/ready bookkeeping and row-count validation, then bypass projection row access when this configured site is zero and neither the independent probe nor private audit needs the row. Let the shared dispatcher continue capture normally. Add a focused regression showing zero projection read/write counters and unchanged live delivery; the existing no-live zero benchmark does not exercise this combination.

2. **P2 — Registry capacity grows with historical derivations, even when owners are released.** `rebirth/src/rust/rebirth-ffi/src/projection_transfer_boundary.rs:79–94`. Every successful projection registration reserves `admitted_capacity + 1`, then filters expired `Weak` entries into that larger vector. Repeated derive/drop/GC from one source therefore retains capacity `C + n` after `n` derivations even with a constant live-handle count. The registry charge consequently rises by16 bytes per successful call on the admitted64-bit profile, so an otherwise identical later derivation can fail its fixed `max_bytes` only because earlier, fully released experiments occurred. Existing ordinary `LlmHandle::register` reuses capacity. Preserve atomic transfer and the conservative admission bound, but reuse sufficient capacity or choose replacement capacity from the live entries plus candidate instead of unconditionally growing it. A model-free repeated registration/drop control can pin bounded capacity and failure atomicity. The current transfer fixture explicitly asserts `capacity + 1` after dropping an owner and thus codifies, rather than detects, this retention.
