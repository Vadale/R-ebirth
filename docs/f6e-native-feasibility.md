# F6e native feasibility — focused architecture note

Source: `codex/projection-steering`, HEAD `6dd701beb128d267a9c5f7324ace04b2c043589c`, inspected 2026-10-07. Read-only ADR preparation. No build, test, model execution, dependency/vendor edit, or runtime edit was performed. Existing Graphify navigation was used only as a map; its stale graph was checked against current source for every claim below. This does not reopen acceptance of F6a/b/c/d. The F6e specification explicitly separates observing an activation from safely editing it and does not authorize a vendor patch: [plan](../docs/phase6-visual-steering-plan.md#L112).

## Recommendation

Proceed to a **bounded, zero-vendor-patch callback feasibility implementation**, contingent on the concrete contract, for **dense Llama `mlp_out`, dense Llama post-Wo `attn_out`, and Qwen2 `mlp_out` only**. Source supports the necessary synchronous producer boundary on pinned CPU and Metal. It does **not** establish executed numerical/performance acceptance or a portable upstream mutation guarantee. The public callback documentation describes observation, not mutation. A successful downstream capability probe and independent causal goldens are required, not just tensor readback.

The proposed static projection, one entry per `(layer, component)`, at most 32 sites, f64 owned direction/dot/update and checked f32 row writes has no identified source-level contradiction for those three sites. The 32-site cap is a proposed contract choice, not an existing engine limit. Rejecting duplicate sites avoids unspecified noncommuting projection order. Residual schema1 artifacts must not be relabeled as MLP/attention vectors; same width does not identify the space. Projection at engine layer0 is feasible in these builders: the existing additive layer0 restriction is specific to the control-vector API and need not be copied to projection.

Use an explicit graph-op patch only if the callback proof or measured performance fails, or if the approved scope must include unnamed sites such as Qwen2 post-Wo attention. That alternative requires a separate vendor decision; no approval is inferred here.

## What the scheduler and Metal actually guarantee

1. The scheduler asks whether each node needs observation, takes a graph view ending **at that node**, computes that view, synchronizes its backend, then calls `ask=false`. The next view is submitted only after that callback returns. Thus a synchronous write to the selected producer can precede its downstream consumers. This is an inference from the pinned implementation, not a promised mutation API: [scheduler](../rebirth/src/llama.cpp/ggml/src/ggml-backend.cpp#L1802), [documented observation contract](../rebirth/src/llama.cpp/ggml/include/ggml-backend.h#L309).
2. `ggml_backend_tensor_set` is available upstream, routes views to their backing buffer, checks byte extent, and calls the buffer's synchronous setter. CPU uses `memcpy`. Metal shared buffers use `memcpy`; nonshared buffers use a blit and wait on its completion semaphore. Metal synchronization waits for prior command-buffer completion. Therefore the intended M4 shared-memory path has a concrete producer-complete / host-write / downstream-submit ordering. The nonshared setter has a TODO for checking copy errors and an assertion on staging allocation, so do not claim all Metal devices/buffer modes are equivalently proved: [set/get](../rebirth/src/llama.cpp/ggml/src/ggml-backend.cpp#L335), [CPU](../rebirth/src/llama.cpp/ggml/src/ggml-backend.cpp#L2383), [Metal set/get](../rebirth/src/llama.cpp/ggml/src/ggml-metal/ggml-metal-device.m#L2293), [Metal synchronize](../rebirth/src/llama.cpp/ggml/src/ggml-metal/ggml-metal-context.m#L252).
3. Backend graph optimization occurs before callback partitioning. Metal reorders independent operations, but its temporary grouping is unpacked back into individual tensor nodes. Compute receives the supplied graph view; encoding indices are limited to that view, and fusion refuses to extend past them. These facts support the barrier but require an actual Metal causal test with normal optimization/fusion enabled, especially when allocation aliases are present: [scheduler optimization](../rebirth/src/llama.cpp/ggml/src/ggml-backend.cpp#L1453), [Metal unpacking](../rebirth/src/llama.cpp/ggml/src/ggml-metal/ggml-metal-common.cpp#L461), [encoding/fusion bounds](../rebirth/src/llama.cpp/ggml/src/ggml-metal/ggml-metal-ops.cpp#L54), [compute uses graph](../rebirth/src/llama.cpp/ggml/src/ggml-metal/ggml-metal-context.m#L459).
4. Graph reuse is enabled. The eval pointer is installed on the new-graph branch, while reuse retains it. Each compute still executes the scheduler callback. Keep a stable context-owned dispatcher and immutable projection plan; do not toggle callback pointers per request or retain tensor/data pointers across callbacks/decodes. Reset matching/count state for each real microbatch, including reused one-token graphs: [reuse](../rebirth/src/llama.cpp/src/llama-context.cpp#L1364).
5. **Returning false is not an adequate error or cancellation protocol.** At `ask=false` it breaks only the inner node loop for that split; the outer split loop continues and the function can return SUCCESS. The header's “cancel graph compute” comment is stronger than this implementation. Latch the first projection error in owned state, surface it immediately after `llama_decode` before reading logits/sampling/publishing, discard partial output, and explicitly invalidate an unusable context. A callback panic must never unwind across C. Inject failures across more than one backend split in the proof: [outer loop](../rebirth/src/llama.cpp/ggml/src/ggml-backend.cpp#L1664), [break and success](../rebirth/src/llama.cpp/ggml/src/ggml-backend.cpp#L1833), [current outside-decode check](../rebirth/src/rust/rebirth-llm/src/generate.rs#L522).

## Site identity, rows, and aliasing

| Proposed site | Exact current producer/consumer | Required qualification |
|---|---|---|
| Llama `attn_out` | `build_attn` return, named `attn_out`, before optional last-layer `get_rows`, then `ffn_inp = cur + inpSA`. Shared helper applies Wo and optional output scale/bias before returning. | Actual post-Wo F32 producer; do not match pre-Wo `kqv_out`. |
| Dense Llama `mlp_out` | `build_ffn` return named `ffn_out` before `cur + ffn_inp`. | Llama also names the residual sum `ffn_out` before `build_cvec`; that second name can persist when adapters introduce another node, or be overwritten by `l_out` when no adapter does. Name counts alone do not identify the site. |
| Qwen2 `mlp_out` | `build_ffn` return named `ffn_out`, then residual add, `build_cvec`, `l_out`. | Dense producer and expected down-projection chain. |
| Qwen2 `attn_out` | Post-Wo exists as `build_attn` return, but no post-Wo callback name is assigned. | Classed unsupported for the zero-patch named-site contract. `kqv_out` is before Wo and is not a substitute. |

Anchors: [Llama attention](../rebirth/src/llama.cpp/src/models/llama.cpp#L169), [Llama MLP and MoE branch](../rebirth/src/llama.cpp/src/models/llama.cpp#L181), [Qwen2](../rebirth/src/llama.cpp/src/models/qwen2.cpp#L102), [shared attention](../rebirth/src/llama.cpp/src/llama-graph.cpp#L2842), [FFN down projection/bias/scale](../rebirth/src/llama.cpp/src/llama-graph.cpp#L1880), [current architecture map](../rebirth/src/rust/rebirth-llm/src/trace.rs#L260). Graph callbacks assign/overwrite names; they do not create separate operator nodes: [graph naming](../rebirth/src/llama.cpp/src/llama-context.cpp#L2541).

**Real name-only hazard:** Llama's MoE branch emits `ffn_moe_out`, followed by the residual sum named `ffn_out`. “First ffn_out” on that branch would project the residual, not the MLP. Refuse it unless a separate, explicitly supported semantic mapping is proved. Likewise no promotion of gemma3/qwen3/qwen35/gemma4 from the observation map: their source and fixtures were not evaluated in this task.

The allocator reuses parent storage only with matching layout and no remaining competing children/views; it may also allocate future nodes at the same address. Writing the producer at its synchronized boundary is compatible with ordinary downstream in-place consumption, but a tensor address/name is not proof of unique ownership. Reject unexpected view/alias/weight/input cases and unrecognized producer chains. Never write through a cached host pointer or touch tensor metadata/graph edges: [allocator](../rebirth/src/llama.cpp/ggml/src/ggml-alloc.c#L631).

Current Rust FFI deliberately omits tensor_set and keeps `ggml_tensor` opaque. Its row helper checks counts/bytes/contiguity but infers dtype from known operations; an I32 tensor also occupies four bytes per element. It cannot inspect op/source/view semantics. For runtime structural qualification, use a narrow **relm-owned C++ classifier/accessor**, compiled against the pinned headers, returning checked scalar metadata/role without exposing a borrowed Rust layout. The existing native bridge is a suitable build pattern. Adding it is native scope to specify, not a vendor patch or a new dependency: [FFI](../rebirth/src/rust/rebirth-llm/src/ffi.rs#L281), [row checks](../rebirth/src/rust/rebirth-llm/src/trace.rs#L324), [F32 matmul output](../rebirth/src/llama.cpp/ggml/src/ggml.c#L3290), [native bridge](../rebirth/src/rust/rebirth-llm/native/CMakeLists.txt#L1).

Project **every actually computed row** at each registered site in every prefill chunk/microbatch and incremental decode. Do not reuse F6a's final-source-only capture filter. Final-layer MLP may already have output-row pruning; mutate the rows actually present, not an assumed prompt-length tensor. For a contiguous `[H, rows]` F32 matrix, read/write one H-wide row at a checked byte offset, finish finite/range validation of the complete row before its write, then advance. A later row failure still makes the entire decode unusable. Preserve the existing n_batch chokepoint: [generation decode](../rebirth/src/rust/rebirth-llm/src/generate.rs#L488), [F6a filters](../rebirth/src/rust/rebirth-llm/src/live_capture.rs#L98), [last-row copy](../rebirth/src/rust/rebirth-llm/src/live_capture.rs#L297).

## Composition and callback ownership

For one dense block, the proposed deterministic order is:

`a = P_attention(attention(x))`; `u = x + a`; `f = P_mlp(FFN(norm(u)))`; `y = ablate(u + f + additive_steer)`.

Attention projection therefore also changes that block's MLP input; MLP projection does not retroactively change that block's Q/K/V. Both can influence later-layer KV and future-token behavior. Existing `build_cvec` adds first and ablates afterward, so residual pinning still wins at pinned coordinates: [build_cvec](../rebirth/src/llama.cpp/src/llama-graph.cpp#L1509), [KV write before attention output](../rebirth/src/llama.cpp/src/llama-graph.cpp#L2827).

The context owns a boxed stable LiveDispatcher; normal and derived generation contexts install exactly one eval callback. Extend that dispatch point to arbitrate projection and observation. Ask should request a barrier if either needs it. Ready should validate identity, **project first**, then let live capture read the edited tensor. Projection remains active during ordinary generation/logits even when capture is dormant or selects no activations. F6a session teardown must only tear down its observation state, not remove the handle's static projection plan. No R callback, acknowledgement wait, external file I/O, or retained tensor reference belongs in the mutation operation: [context lifetime](../rebirth/src/rust/rebirth-llm/src/engine.rs#L280), [derived install](../rebirth/src/rust/rebirth-llm/src/engine.rs#L732), [dispatcher install](../rebirth/src/rust/rebirth-llm/src/live_capture.rs#L90), [ready copy](../rebirth/src/rust/rebirth-llm/src/live_capture.rs#L318), [capture-only early exit and Drop](../rebirth/src/rust/rebirth-llm/src/live_capture.rs#L458).

Existing trace and sentinel contexts install their own callback with separate stable state. They cannot simply inherit the generation dispatch pointer. Public `llm_trace()` currently **rejects intervened handles**, explicitly because its fresh context does not inherit adapters. Preserve that restriction unless the concrete F6e contract expands it; post-edit measurement can use existing live generation. Any future intervened trace needs intentional plan attachment and a composite callback of its own: [trace restriction](../rebirth/R/trace.R#L40), [trace owner](../rebirth/src/rust/rebirth-llm/src/trace.rs#L700), [trace context](../rebirth/src/rust/rebirth-llm/src/engine.rs#L654).

Static projection and F6b additive-only replies are compatible. Rebuild derived handles from the full original intervention specification so adding an ablation/steer cannot silently drop existing projection entries. Keep projection entries out of LiveSteering's coefficient list/reply indices/audit. Its authoritative baseline comparison and restore affect the additive adapter only. F6b updates after state k continue before decoding sampled token k; no earlier KV replay and no projection coefficient updates are implied: [derive](../rebirth/src/rust/rebirth-llm/src/intervene.rs#L235), [reply timing](../rebirth/src/rust/rebirth-llm/src/generate.rs#L1105), [additive application](../rebirth/src/rust/rebirth-llm/src/live_steering.rs#L247).

On cancellation/failure, stop further writes once cancellation is observed, latch failure, return to the outside-decode boundary, and expose no state/token/logits from the partial step. Only quiescent, demonstrably reusable contexts may be returned; poison/close the handle if callback/backend failure leaves that unproved. Immutable projection plan ownership lasts until context destruction; borrowed direction pointers must never outlive it. No graph-buffer “undo” is appropriate: new decodes recompute scratch, while KV must be cleared/disposed on failed calls. Preserve the existing additive restoration guard and async panic/invalidation path: [restore](../rebirth/src/rust/rebirth-llm/src/live_steering.rs#L282), [worker cleanup](../rebirth/src/rust/rebirth-llm/src/async_job.rs#L875).

## Why not start with a graph-op patch?

An explicit graph operator built from existing reductions/broadcast/multiply/subtract could put projection in the dependency graph at the builder site. That is stronger for placement, alias analysis and backend scheduling, avoids host row transfers and permits Qwen2's unnamed post-Wo site. It requires new immutable adapter state/setter/builder integration, graph-reuse topology/input accounting, backend support and memory reservations, plus approved vendor provenance updates. Standard F32 GGML arithmetic also does not reproduce the proposed f64-dot/f64-update contract automatically; a custom high-precision kernel would be additional scope. Available primitive declarations: [sub](../rebirth/src/llama.cpp/ggml/include/ggml.h#L956), [sum/repeat](../rebirth/src/llama.cpp/ggml/include/ggml.h#L1048).

The callback bridge is smaller and fits the three already named sites with one bounded row, but pays a scheduler barrier and CPU computation per selected tensor and row transfer per row. At many sites/prefill tokens, Metal synchronization can dominate. The absence of a vendor diff does not waive mutation safety evidence. Keep graph-op work as the stated alternative if the bounded bridge fails, not an unapproved fallback implemented silently.

## Required evidence before native acceptance

- Independent fixtures must verify the proposed exact arithmetic (f64 immutable v, defined neuron summation order, f64 update, checked f32 cast), alpha0 identity, alpha1 removal, negative-alpha amplification, preserved orthogonal component, non-unit/nonfinite/overflow rejection, and propagation through downstream residual/MLP/logits. Name-only/readback-only assertions are insufficient.
- A new **site-specific downstream sentinel**, before returning a usable projected handle, must exercise the same classifier/write path and prove downstream consumption. Existing additive `steer_ok` cannot attest projection. Use fresh bounded contexts and a canonical direction with a measured nonzero component; inconclusive zero signal must not pass. Attention can check its immediate `ffn_inp` consumer; MLP can check the immediate residual sum in a clean probe. Cache by model/backend/implementation/site/layer with bounded storage; failed probes never mark success. Inject a no-write bridge and wrong-site bridge to prove discrimination. Existing probe is precedent, not sufficient acceptance: [probe](../rebirth/src/rust/rebirth-llm/src/probe.rs#L330).
- Cover Llama's duplicate/overwritten MLP names and MoE refusal, Qwen2 post-Wo refusal, final-layer pruning, prompt >n_batch and >n_ubatch, all relevant rows, repeated one-token graph reuse, CPU, actual Metal device/offload and backend splits. Record accepted producer chain/layout/alias qualification; fail closed when it changes.
- Verify live post-edit capture plus ordinary logits/generation; original-handle isolation; projection retained through additive/ablation derivation; F6b zero/change/restore with static projection; cancel/close/invalid reply/panic/partial write and failed capability paths. No resetting or replacing the callback during graph reuse.
- Preflight charges actual capacities: up to `8*H*S` direction data plus owned descriptors/Arc copies as implemented, `4*H` row scratch, finite-check/scalar state, site counters, plan copies, bounded classifier/probe metadata, probe scratch and cache, in addition to existing live/FFI/R peak. No H-by-token capture, dense H-by-H projector, or uncharged per-row allocation. Retain existing materialization/transport/spill limits and twin every new R/Rust term. Probe memory must be explicit; previous F6b experience rules out assuming it is free.
- Use optimized production-representative CPU/Metal timing with honest device receipts. Compare same-build ordinary baseline, projection-disabled/alpha0, a declared single-site projection and the intended bounded multi-site case; measure prefill and generation separately. Prior F6a timings do not accept this new write/synchronization work. Preserve failure receipts, do not alter numerical/performance thresholds after observing results.

**Conclusion:** no inherent pinned-source blocker was found for a carefully qualified synchronous callback bridge at the three dense named sites. Missing Qwen2 post-Wo naming, opaque FFI's insufficient structural introspection, independent projection/capture lifetimes, and false-return error propagation are concrete design obligations. Safe editable placement and performance remain untested, so the outcome is a conditional architecture recommendation, not feature acceptance.
